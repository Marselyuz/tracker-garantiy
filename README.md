# Трекер гарантий — полный проект с нуля (Laravel 10)

Это уже целый Laravel-проект (скелет взят напрямую с GitHub laravel/laravel),
а не просто набор файлов поверх твоего старого. Внутри есть всё: composer.json,
artisan, .env, конфиги, миграции, контроллеры, вьюхи, стили.

## Чего внутри НЕТ (и почему)
- vendor/ — папка с библиотеками (тысячи файлов), её никогда не кладут в архив,
  она ставится командой composer install у тебя локально (интернет нужен только для этого шага)
- node_modules/ — то же самое, но для JS (нам для Blade-вёрстки даже не понадобится)

## Установка (Open Server или любой локальный сервер с PHP 8.1+)
1. Распакуй архив в папку проекта (например, domains/warranty-tracker в Open Server)
2. В терминале в корне проекта:
   composer install
   php artisan key:generate
3. Открой .env и проверь настройки БД (DB_DATABASE, DB_USERNAME, DB_PASSWORD) —
   создай пустую базу warranty_tracker в phpMyAdmin (или поменяй имя на своё)
4. Прогони миграции и создай симлинк для загруженных файлов:
   php artisan migrate
   php artisan storage:link
5. Открой сайт в браузере, начни с /register

## Что реализовано
- Регистрация / вход / выход — ручная авторизация (AccountController, Auth::attempt()),
  как в твоём прошлом проекте, без Breeze
- Дашборд со сводкой: сколько чеков, сколько гарантий активно/истекает/истекло
- Добавление чека вручную (магазин, дата, фото) — OCR не подключён, это следующий шаг
- Товары внутри чека: добавление/редактирование/удаление, статус гарантии считается
  автоматически от даты (без базы/крона — метод getWarrantyStatusAttribute() в модели Item)
- Список гарантий с фильтром по статусу
- Профиль с галочкой "присылать уведомления" — сохраняется в БД, но письма пока не отправляются

## Структура БД
- users: id, username, email, password, role, notifications_enabled
- receipts: id, user_id, store_name, purchase_date, image, status
- items: id, receipt_id, name, price, warranty_months, warranty_end_date
